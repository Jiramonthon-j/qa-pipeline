## 2) จุดสำคัญที่ต้องอธิบายก่อน เพราะมีผลกับพฤติกรรมจริง

**เรื่อง [?] เมนูท้ายรายงาน — ไม่ใช่ prompt ที่รอ input จาก Terminal จริงๆ**

สคริปต์ `list-preview` รันผ่าน Claude (ไม่ใช่ผู้ใช้เปิด Terminal เองมาพิมพ์) ดังนั้นเมนู `[?] ...` ด้านบนเป็นแค่ **ข้อความที่พิมพ์ออกมาเฉยๆ** (ไม่มีการ `input()` รอค่าจริงในสคริปต์ — ถ้าใส่ไปจะทำให้สคริปต์ค้างรอ input ที่ไม่มีวันมาถึงเวลา Claude เป็นคนรัน) พอ Claude เห็นผลลัพธ์นี้แล้ว จะ:

1. Paste รายงานนี้ให้ผู้ใช้ดูในแชทตรงๆ ตามที่สคริปต์พิมพ์จริง (ไม่สรุปเอง ไม่แต่งข้อมูลเพิ่ม)
2. ใช้เครื่องมือถามคำถามจริง (AskUserQuestion) ถามผู้ใช้ 4 ตัวเลือกเดียวกันนี้ (All / Select / Export Excel / Cancel)
3. **ถ้าเลือก "Select เฉพาะบางเคส"** — Claude จะถามต่ออีกรอบให้ผู้ใช้เลือกได้ว่าจะเอา Bug# ไหนบ้าง (เลือกได้หลายอันจากลิสต์ชื่อ Bug ที่เห็นจริง ไม่ต้องพิมพ์เลขเอง กันพิมพ์ผิด)

พูดง่ายๆ คือ **ตัวเลข/รายการที่เห็นในรายงานเป็นของจริงจากสคริปต์เสมอ (ไม่ได้ให้ Claude แต่งเอง) แต่การ "เลือก Action" จะทำผ่านหน้าต่างถามคำถามในแชท ไม่ใช่พิมพ์ตอบใน Terminal โดยตรง**

## 3) จุดที่เคยถามไว้ก่อนใส่ลง Skill จริง — สรุปผลตัดสินใจสุดท้าย

1. **"Severity" → "Priority"**: ตัดสินใจแล้วว่าใช้ Priority (P0-P3) ตรงๆ ไม่มี Severity แยก เพราะ Workbook ไม่มีคอลัมน์นี้จริง และไม่อยากเดา mapping เอง
2. **"Remark"**: ใช้ค่าเดียวกับ Summary บรรทัดแรกของ Description ที่ยืนยันไว้ใน `mockup-defect-format.md` แล้ว (ไม่สร้าง logic สรุปข้อความซ้ำสองที่)
3. **เคสที่ข้ามอัตโนมัติ (มี Issue link อยู่แล้ว)**: แสดงแค่จำนวนรวม (บรรทัด "⏭ ข้ามอัตโนมัติ...") ไม่แสดงรายละเอียดทีละ TC-ID ในรายงานนี้ — ใช้ค่า default ที่แนะนำไว้เพราะผู้ใช้ไม่ได้ทักท้วง
4. **ลำดับ Bug# ตอนมีหลายเคส**: เรียงตาม Priority ก่อนเสมอ (P0 มาก่อน P3) — ใช้ค่า default ที่แนะนำไว้
5. **ถ้าเลือก Cancel**: จบ Skill ทันที ตั้ง Stage 09 เป็น `ยังไม่เปิด Ticket (ผู้ใช้ยกเลิก N เคสที่พบ)` ไม่แก้ไฟล์ใดๆ ในโปรเจค — ใช้ค่า default ที่แนะนำไว้
6. **Action ใหม่ "[3] Export เป็นไฟล์ Excel"**: ตัดสินใจให้สร้างจริง — ได้ไฟล์ `09-redmine-bugs-export.xlsx` ในโฟลเดอร์ Feature (คอลัมน์: No. / Test Case ID / Module / Title / Priority / Remark / Screenshot Path / Subject / Description) **ไม่ถือว่าเปิด Ticket แล้ว** จึงไม่แก้คอลัมน์ "Issue link" ใน Workbook และ Stage 09 จะเป็น `Complete (Export เท่านั้น — ยังไม่เปิด Ticket จริง N เคส)` แทน `Complete` เฉยๆ
