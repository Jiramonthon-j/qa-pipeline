# Mockup: Format ของ qa-retest-closure (Skill 10a)

> **สถานะ: ยืนยันแล้วทั้ง 3 Format เขียนลง SKILL.md และ `scripts/close_redmine_issues.py` / `scripts/send_email_notification.py` (คำสั่ง `build-retest-failed-body`) จริงแล้ว**

ทดสอบด้วย TC-017 (Pass) และ TC-021 (Fail) เป็นตัวอย่าง — ข้อมูลสมมติเพื่อประกอบ Mockup เท่านั้น

## Format ที่ 1 — Comment กรณี Pass (Verified แล้ว ก่อนปิด Ticket)

```
✅ Retest → Pass

เรื่องที่แก้ไข: TC-017 — ลบโค้ด A แล้วใส่โค้ด B ต่อทันที

**ผลการ Retest:** Pass — พฤติกรรมของระบบตรงตาม Expected Result แล้ว
**วันที่ Retest:** 05 Sep 2026
**ผู้ทดสอบ/ระบบ:** QA Automation Assistant

📎 แนบไฟล์ภาพผลการ Retest (Pass) ประกอบคอมเมนต์นี้
```

พร้อมแนบไฟล์ Screenshot ผล Retest จริงเป็น Attachment บน Ticket (อัปโหลดผ่าน Redmine Attachments API จริง — ของใหม่ที่เขียนเพิ่มสำหรับ Skill นี้ ไม่ใช่แค่ path ข้อความแบบ Skill 09) แล้วตั้ง Status ของ Ticket เป็นชื่อที่ผู้ใช้ระบุ (เช่น "Closed")

## Format ที่ 2 — Comment กรณี Fail (ยังไม่ผ่านหลัง Retest)

```
❌ Retest → Fail

เรื่องที่ Retest: TC-021 — ใช้โค้ดส่วนลดซ้อนกัน

**ผลการ Retest:** Fail — ยังพบปัญหาอยู่ ไม่ตรงตาม Expected Result
**สาเหตุที่ไม่ผ่าน:** ยังลบสิทธิ์การใช้โค้ดไม่ถูกต้องเมื่อใช้ 2 โค้ดพร้อมกัน
**วันที่ Retest:** 05 Sep 2026
**ผู้ทดสอบ/ระบบ:** QA Automation Assistant

📎 แนบไฟล์ภาพผลการ Retest (Fail) ประกอบคอมเมนต์นี้
```

พร้อมแนบไฟล์ Screenshot ผล Retest จริงเช่นเดียวกัน **ไม่แตะ Status ของ Ticket เลย** (Ticket ยังเปิดอยู่รอ Dev แก้ต่อ)

หมายเหตุ: `**สาเหตุที่ไม่ผ่าน**` ใช้ Markdown bold ตัวอย่าง — ถ้า Redmine instance ตั้งค่าเป็น Textile จะกลายเป็น `*สาเหตุที่ไม่ผ่าน*` แทน (สคริปต์จัดการให้อัตโนมัติตาม `--syntax` ที่ระบุ)

## Format ที่ 3 — Email แจ้ง Dev ซ้ำ (กรณี Retest แล้วยัง Fail อย่างน้อย 1 เคส)

อ้างอิงโครงจาก Format อีเมลของ Skill 09 ("DEFECT SUMMARY REPORT") แต่ปรับเนื้อหาให้เป็นแนว Retest ไม่ผ่านแทน — เปลี่ยน 3 จุด: (1) ประโยคเปิดพูดถึง Retest ไม่ใช่บั๊กใหม่ (2) แบนเนอร์เปลี่ยนชื่อ/อีโมจิ และ "Test Run Date" → "Retest Date" (3) ตัดหัวข้อ Description/Steps to Reproduce ออก แทนที่ด้วย "สาเหตุที่ไม่ผ่าน" (ค่าเดียวกับที่คอมเมนต์กลับ Ticket ไปแล้วจาก Format ที่ 2) และอ้างอิงกลับไปดูรูปที่ Comment ของ Ticket แทนการแนบรูปซ้ำในอีเมล (ยืนยันแล้วว่าไม่ต้องแนบซ้ำเพราะรูปถูกแนบเข้า Comment ของ Redmine ไปแล้ว)

```
Hi Dev Team,

ระบบ QA Automation ได้ทำการ Retest ตามที่แจ้งว่าแก้ไขแล้วเสร็จสิ้น แต่พบว่ายังมี Defect ที่ยังไม่ผ่านจำนวน 2 รายการ
รายละเอียดและลิงก์สำหรับเข้าดู Ticket ใน Redmine ถูกสรุปไว้ด้านล่างนี้ครับ:

================================================================================
🔁 RETEST FAILED REPORT
================================================================================
Retest Date: 05 Sep 2026 | Environment: Staging (mock) — Chromium
--------------------------------------------------------------------------------
1. [P0 - Critical] โค้ดหมดอายุยังใช้ได้
--------------------------------------------------------------------------------
• Issue Link       : https://redmine.example.com/issues/1040
• Module           : ตะกร้าสินค้า
• Test Case        : TC-030
• สาเหตุที่ไม่ผ่าน : ระบบไม่เช็ควันหมดอายุของโค้ดก่อนอนุมัติส่วนลด
• ดูภาพประกอบเพิ่มเติมได้ที่ Comment ล่าสุดของ Defect#1040
--------------------------------------------------------------------------------
2. [P1 - High] ใช้โค้ดซ้อนกัน
--------------------------------------------------------------------------------
• Issue Link       : https://redmine.example.com/issues/1030
• Module           : โปรไฟล์
• Test Case        : TC-021
• สาเหตุที่ไม่ผ่าน : ยังลบสิทธิ์ไม่ถูกต้องเมื่อใช้ 2 โค้ดพร้อมกัน
• ดูภาพประกอบเพิ่มเติมได้ที่ Comment ล่าสุดของ Defect#1030
================================================================================
📁 Attached Evidence:
- ไฟล์ Screenshot ผลการ Retest (Fail) ได้ถูกแนบเข้าไปในคอมเมนต์ล่าสุดของ Ticket แต่ละใบเรียบร้อยแล้ว
- สามารถคลิกที่ Issue Link ด้านบนเพื่อดูรายละเอียดเพิ่มเติมและอัปเดต Status ได้ทันทีครับ

Best regards,
QA Automation Assistant
--------------------------------------------------------------------------------
```

ทดสอบจริงแล้วผ่านคำสั่ง `python3 scripts/send_email_notification.py build-retest-failed-body` — output ตรงตาม Mockup นี้เป๊ะ (เรียงตาม Priority ก่อนเสมอ P0 มาก่อน P1)
