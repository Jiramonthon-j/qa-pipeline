## ชุดข้อมูลกลาง (ใช้ร่วมกันหลาย Test Case)

### Pre-seeded Subscriber — สำหรับทดสอบเคสสมัครซ้ำ

ก่อนเริ่มรัน Automation ต้องเตรียมข้อมูลอีเมลที่ "สมัครไปแล้วล่วงหน้า" ในระบบ subscriber (staging) ให้มีอยู่จริงก่อนรัน Test Case ที่ทดสอบการสมัครซ้ำ:

| อีเมลที่ต้อง Pre-seed | ใช้โดย |
|---|---|
| `dup01@example.com` | TC-004 (ทดสอบสมัครซ้ำแบบ exact match) |
| `dup02@example.com` | TC-005 (ทดสอบสมัครซ้ำแบบตัวพิมพ์ต่างกัน — ต้อง seed เป็นตัวพิมพ์เล็กทั้งหมดตามนี้เป๊ะๆ) |

วิธี Seed: รันขั้นตอน TC-001 (happy path signup) ด้วยอีเมลทั้งสองนี้ก่อนเริ่มรอบทดสอบจริง แล้วค่อยรัน TC-004/TC-005 ต่อ

## Mock Data รายเคส

### TC-001: สมัครรับข่าวสารสำเร็จด้วยอีเมลรูปแบบถูกต้องที่ยังไม่เคยสมัคร
`email = newuser01@example.com` — ค่าคงที่ อีเมลรูปแบบถูกต้องมาตรฐาน ยังไม่เคยอยู่ใน subscriber

### TC-002: กรอกอีเมลรูปแบบไม่ถูกต้อง (ไม่มี @)
`email = newuserexample.com` — ค่าคงที่ จงใจไม่มี `@` เพื่อละเมิด BR-001

### TC-003: กรอกอีเมลรูปแบบไม่ถูกต้อง (มี @ แต่ไม่มีโดเมน)
`email = newuser@` — ค่าคงที่ จงใจไม่มีส่วนโดเมนหลัง `@`

### TC-004: สมัครซ้ำด้วยอีเมลเดิมทุกตัวอักษร (exact match)
`email = dup01@example.com` — ใช้ชุดข้อมูลกลาง "Pre-seeded Subscriber" ต้อง seed ให้เหมือนกันทุกตัวอักษรก่อนรันเคสนี้

### TC-005: สมัครซ้ำด้วยอีเมลเดิมแต่ตัวพิมพ์เล็ก-ใหญ่ต่างกัน
`email ที่ seed ไว้ = dup02@example.com` (ตัวพิมพ์เล็กทั้งหมด) / `email ที่กรอกทดสอบ = Dup02@Example.com` (สลับตัวพิมพ์บางตัว) — ทั้งสองค่าคงที่ ใช้ชุดข้อมูลกลาง "Pre-seeded Subscriber"

### TC-006: กดปุ่ม "สมัครรับข่าวสาร" ซ้ำระหว่างระบบกำลังประมวลผล
`email = nodouble01@example.com` — ค่าคงที่ อีเมลรูปแบบถูกต้อง ยังไม่เคยสมัคร (ไม่ต้องใช้ร่วมกับชุดข้อมูลกลาง เพราะจุดประสงค์ทดสอบคือจังหวะการกดปุ่ม ไม่ใช่ผลของ BR-002)

### TC-007: กดปุ่มสมัครโดยไม่กรอกอีเมลเลย (ช่องว่าง)
`email = ""` (ช่องว่าง) — ค่าคงที่ ไม่ต้อง mock อะไรเพิ่มเติมนอกจากปล่อยว่าง

### TC-008: กรอกอีเมลที่มีช่องว่างนำหน้า/ตามหลัง
`email = " spaced01@example.com "` (มีช่องว่าง 1 ตัวนำหน้าและตามหลัง) — ค่าคงที่

### TC-009: กรอกอีเมลที่ยาวผิดปกติ
`email = "<local-part 250 ตัวอักษร a-z ซ้ำ>@example.com"` — ค่าคงที่ สร้างจากสตริง `"a" * 250 + "@example.com"` ตอนรัน Automation (ไม่ต้อง hardcode สตริงยาวในเอกสารนี้ ให้ Automation Script generate ขึ้นตรงๆ)

### TC-010: ตรวจสอบว่า Footer widget แสดงผลและทำงานถูกต้องข้าม Browser หลัก
`email = crossbrowser01@example.com` ต่อ 1 รอบ Browser (ใช้ค่าเดียวกับ pattern ของ TC-001 ทำซ้ำบน Chrome/Safari/Firefox/Edge) — ค่าคงที่ ไม่ต้องแยกอีเมลต่อ Browser เพราะแต่ละรอบทดสอบแยก environment กันอยู่แล้ว ไม่ชนกัน

### TC-011: ระบบบันทึกอีเมลลง subscriber ล้มเหลวจากสาเหตุฝั่งระบบเอง
`email = infrafail01@example.com` — ค่าคงที่ ส่วนสภาพ "subscriber DB unavailable" เป็นการจำลองสภาพแวดล้อม ไม่ใช่ Test Data ของอีเมล — ระบุไว้ชัดเจนว่าเป็นสิ่งที่ Automation Script (06a) ต้อง mock/stub ที่ระดับ environment ไม่ใช่ค่าที่ป้อนผ่านฟอร์ม

## หมายเหตุ

ไม่มี Test Case ใดในรอบนี้ที่ต้องใช้ค่า Dynamic (เช่น OTP/Token ที่ระบบสุ่มส่งจริง) เพราะฟีเจอร์นี้ไม่มีขั้นตอนยืนยันตัวตนหรือ Double Opt-in (ตาม BR-003) — Mock Data ทั้งหมดจึงเป็นค่าคงที่ที่กำหนดไว้ล่วงหน้าได้ทั้งหมด อีเมลทุกตัวใช้โดเมน `example.com` เท่านั้น ไม่ใช่อีเมลของบุคคลจริง
