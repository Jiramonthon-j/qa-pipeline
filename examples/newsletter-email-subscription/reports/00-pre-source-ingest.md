## สรุปจากแต่ละแหล่ง

### แหล่งที่ 1: สเปก Newsletter Email Subscription v1 (Nan, Product)

สเปกนี้อธิบายฟีเจอร์เพิ่มช่องกรอกอีเมลใน Footer ของเว็บไซต์ ให้ผู้ใช้ทั่วไปที่ไม่ต้อง Login สมัครรับข่าวสารได้ **UI** เป็น input ช่องเดียว ("อีเมลของคุณ") คู่กับปุ่ม "สมัครรับข่าวสาร" และผลลัพธ์ (สำเร็จ/error) แสดงแบบ inline ใต้ปุ่ม ไม่ใช่ popup

**Business Rule หลัก** มี 4 ข้อ: ต้องกรอกในรูปแบบอีเมลที่ถูกต้องไม่งั้นขึ้น error "กรุณากรอกอีเมลให้ถูกต้อง"; ถ้าอีเมลเคยสมัครไปแล้วห้ามสมัครซ้ำและขึ้น error "อีเมลนี้สมัครรับข่าวสารไปแล้ว"; ถ้าผ่านทั้งสองเงื่อนไขให้บันทึกลงฐานข้อมูล subscriber แล้วขึ้นข้อความสำเร็จ "สมัครรับข่าวสารสำเร็จ ขอบคุณที่ติดตามเรา"; และปุ่มกดซ้ำระหว่างระบบประมวลผลไม่ได้เพื่อกัน double submit

**ขอบเขตที่ไม่รวมใน v1**: ไม่มี Double Opt-in (ไม่ต้องส่งอีเมลยืนยันก่อนนับว่าสมัครสำเร็จ) และไม่มีหน้า Unsubscribe ในตัว (ให้ผ่าน Support แทน) — ทั้งสองเรื่องเป็นแผนสำหรับ v2 ทดสอบบน Environment Staging ที่ `https://staging.example-shop.test/`

### แหล่งที่ 2: Slack chat log #newsletter-signup (Nan × Beam)

บทสนทนาสั้นๆ ต่อยอดจากสเปก มี 2 ประเด็นที่ Beam (Dev) ถามเพิ่ม **เรื่องเช็คอีเมลซ้ำแบบ case-insensitive**: Beam ถามว่า `Test@Mail.com` กับ `test@mail.com` ควรนับเป็นอีเมลเดียวกันไหม Nan ตอบว่าเรื่องนี้สเปกยังไม่ได้พูดถึง จะไปถามทีม Marketing อีกที และให้ Beam ทำแบบ **exact match (case-sensitive) ไปก่อน** โดยยังไม่ได้ปิดจบว่าจะเปลี่ยนหรือไม่ **เรื่องความยาวอีเมลสูงสุด**: Nan ถามว่ามีลิมิตความยาวเพิ่มไหม Beam ตอบว่าปล่อยตาม standard email format ไปเลย ไม่จำกัดความยาวเพิ่มเอง — ข้อนี้ถือว่าปิดจบแล้วในบทสนทนา

## จุดที่ข้อมูลขัดแย้งหรือเป็นช่องว่าง (ต้องเติมก่อนหรือรับทราบก่อนไปขั้น 01)

1. **เช็คอีเมลซ้ำแบบ case-sensitive หรือไม่ยังไม่ได้ปิดจบ** — สเปก (SRC-001) เขียนแค่ว่า "ถ้าอีเมลนี้เคยสมัครไปแล้วห้ามสมัครซ้ำ" โดยไม่ระบุเรื่อง case ส่วน Slack log (SRC-002) ให้ Dev implement แบบ exact match (case-sensitive) ไปก่อนชั่วคราว โดย Nan บอกว่าจะไปถามทีม Marketing อีกทีและยังไม่มีคำตอบสุดท้ายกลับมาในแหล่งข้อมูลชุดนี้ — เท่ากับว่าพฤติกรรมตอนนี้ (exact match) เป็นการตัดสินใจชั่วคราว ไม่ใช่ข้อสรุปที่ผ่านการยืนยันจากทีม Marketing แล้ว
2. **ยังไม่มีข้อมูลผู้รับผิดชอบ (Owner) ของฟีเจอร์นี้ฝั่ง QA/Sign-off ที่ชัดเจน** — ทั้งสองแหล่งไม่ได้ระบุว่าใครเป็นคนอนุมัติขั้นสุดท้ายก่อนขึ้น Production

## สรุปภาพรวม (Synthesis)

ฟีเจอร์นี้ค่อนข้างเล็กและขอบเขตชัดเจน: เพิ่มช่องกรอกอีเมลใน Footer ให้คนทั่วไปสมัครรับข่าวสารได้ โดยมี 3 พฤติกรรมหลักที่ต้องทดสอบคือตรวจรูปแบบอีเมล ป้องกันการสมัครซ้ำ และบันทึกลงฐานข้อมูลพร้อมข้อความสำเร็จ ทั้งสองแหล่งข้อมูลสอดคล้องกันเรื่อง Business Rule หลักและขอบเขตที่ไม่รวมใน v1 (ไม่มี Double Opt-in ไม่มีหน้า Unsubscribe)

จุดที่ยังต้องระวังคือ **การเช็คอีเมลซ้ำตอนนี้ทำแบบ case-sensitive ตามที่ Dev คุยไว้ใน Slack เป็นการตัดสินใจชั่วคราวที่ยังไม่ได้ผ่านการยืนยันจากทีม Marketing** — ถ้าพฤติกรรมจริงที่ผู้ใช้คาดหวังคือ case-insensitive (ซึ่งเป็นเรื่องปกติสำหรับอีเมล) จุดนี้อาจกลายเป็นช่องโหว่ให้คนสมัครซ้ำได้ด้วยการเปลี่ยนตัวพิมพ์เล็ก-ใหญ่ในอีเมลเดิม ควรให้ `requirement-review` ประเมินความเสี่ยงของจุดนี้ต่อ ไม่ใช่ปิดจบเองในขั้นตอนนี้
